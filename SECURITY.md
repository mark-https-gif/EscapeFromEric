ЗАЩИТА ИГРЫ — КАК УСТРОЕНО И КАК НЕ СЛОМАТЬ
Escape From Eric

--------------------------------------------------------------------------------
1. ЧТО ЗАЩИЩАЕТ КЛИЕНТ
--------------------------------------------------------------------------------
Assets/Scripts/Core/AntiCheat.cs

  1) отладчик (Debugger.IsAttached + IsDebuggerPresent);
  2) процессы читерских инструментов (Cheat Engine, x64dbg, dnSpy, Frida...);
  3) целостность файлов по манифесту <Игра>_Data/integrity.dat;
  4) спидхак (сравнение Time.unscaledDeltaTime с системным Stopwatch).

Проверка целостности асимметричная:

  • Tools/integrity_key.txt — ПРИВАТНЫЙ ключ RSA-2048. Лежит вне Assets,
    в сборку не попадает, распространять его нельзя.
  • AntiCheat.cs — ПУБЛИЧНЫЙ ключ (PublicModulusBase64) только для проверки.

Подделать integrity.dat под изменённый GameAssembly.dll без приватного ключа
нельзя. Раньше там был общий HMAC-секрет прямо в клиенте — его можно было
прочитать в бинарнике и пересобрать манифест. Теперь нельзя.

Подписываются: GameAssembly.dll, UnityPlayer.dll, globalgamemanagers,
resources.assets, level0, sharedassets0.assets, ScriptingAssemblies.json
и Managed/Assembly-CSharp.dll (если это Mono-сборка).

--------------------------------------------------------------------------------
2. ЧТО ЗАЩИЩАЕТ СЕРВЕР
--------------------------------------------------------------------------------
Assets/Scripts/Net/EricEyeServer.cs  — «ERIC'S EYE», серверный античит:
  мусорный ввод (NaN/Inf), магнитуда ввода > 1, откат тика, флуд пакетами,
  фактическая скорость выше лимита. 5 страйков = отключение клиента.

Assets/Scripts/Net/NetRuntime.cs — хендшейк версии при подключении.
  Клиент присылает "EFE|<Application.version>|<ProtocolVersion>".
  Сервер сравнивает и отклоняет всё, что не совпало, ещё до спавна игрока.
  Поэтому взломанная или устаревшая сборка в мир не попадает.

Сервер — источник истины: клиент шлёт только ввод, позицию, скорость,
поимку и урон считает сервер.

--------------------------------------------------------------------------------
3. СБОРКА РЕЛИЗА — ОБЯЗАТЕЛЬНЫЕ ПРАВИЛА
--------------------------------------------------------------------------------
3.1. Только IL2CPP. Mono-сборка содержит Assembly-CSharp.dll, из которой
     исходный код восстанавливается за минуту (ILSpy/dnSpy). Mono — только
     для локальных проверок, никогда для раздачи.
3.2. Только релизные методы: BuildScript.BuildIL2CPP (Windows),
     BuildScript.BuildAndroid (APK), BuildScript.BuildiOS.
     Dev-методы (BuildDev, BuildDevIL2CPP, BuildDevServer) не отдавать никому:
     в них античит работает в режиме наблюдения и вшиты отладочные клавиши.
3.3. Стриппинг: релиз IL2CPP собирается с ManagedStrippingLevel.High,
     dev — Low. Настраивается в BuildScript автоматически.
3.4. Никогда не отдавать игрокам:
       - папку Tools/ (там приватный ключ),
       - папку EscapeFromEric_BackUpThisFolder_ButDontShipItWithYourGame,
       - исходники и Library/.

--------------------------------------------------------------------------------
4. ЧТО ДЕЛАТЬ, ЕСЛИ КЛЮЧ УТЁК
--------------------------------------------------------------------------------
4.1. Сгенерировать новую пару: удалить Tools/integrity_key.txt и запустить
     Tools/gen_key.ps1 (или попросить сборщика), затем вставить новый modulus
     в AntiCheat.cs (PublicModulusBase64).
4.2. Пересобрать релиз. Старые клиенты после этого не пройдут проверку
     целостности, а сервер их не пустит по версии.
4.3. Приватный ключ хранить в одном месте + резервная копия.
     Потеря ключа = невозможность подписать следующий релиз (лечится
     генерацией новой пары и пересборкой клиента).

--------------------------------------------------------------------------------
5. ГРАНИЦЫ ЗАЩИТЫ (честно)
--------------------------------------------------------------------------------
• Клиентскую защиту можно обойти патчем GameAssembly.dll — это всегда возможно,
  если у атакующего есть время и навыки. Цена обхода высокая, а выгода в
  сетевом режиме нулевая, потому что вердикт выносит сервер.
• Имена классов и методов в IL2CPP-сборке видны через Il2CppDumper
  (это норма для Unity). Тела методов — только нативный код.
• Android/iOS: integrity.dat внутри APK/IPA, файловая проверка пропускается,
  целостность обеспечивает подпись пакета.
• Античит не использует драйверы и не читает память чужих процессов
  (по требованию проекта).
